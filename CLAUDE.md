# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Empire Hub — a Telegram-based music-industry simulation game ("Empire Play"). Single TanStack Start (React) app deployed as one Cloudflare Worker, with Google Sheets as the primary datastore (plus a D1 database in progress for a partial migration) and a separate Telegram-media microservice for video streaming.

## Commands

```bash
npm run dev          # vite dev server (frontend)
npm run build         # vite build + scripts/fix-start-manifest.mjs
npm run deploy         # build + wrangler deploy (what CI runs)
npm run lint          # eslint .
npm run format         # prettier --write .
```

Typecheck frontend and backend **separately** — there is no single project-wide typecheck:

```bash
npx tsc --noEmit -p .            # frontend (src/**), uses root tsconfig.json
cd backend && npx tsc --noEmit   # backend (backend/src/**), no local tsconfig — tsc falls back to compiling all .ts under cwd
```

Always run both before pushing backend changes, since `backend/src` is imported directly by the frontend's Worker entry (`src/server.ts`) and compiled together at build time.

There is no test suite in this repo.

**New route files**: after adding a file under `src/routes/`, run `npx vite build` once to regenerate `src/routeTree.gen.ts` (checked into git, auto-generated by TanStack Router's codegen plugin) — otherwise TypeScript errors on any `to:` prop referencing the new route.

## Deploy workflow

This is a solo-maintained production app with no staging environment — `main` is live. The working branch for AI-assisted sessions is `claude/empire-hub-spotify-redesign-7ytmb6` (or whatever branch the session started on); the deploy cycle is:

```bash
git push origin <working-branch>                                  # keep work saved
git fetch origin main
git checkout -B tmp-deploy-mainN origin/main
git cherry-pick <sha...>                                          # resolve conflicts keeping both sides' logic if complementary
cd backend && npx tsc --noEmit && cd .. && npx tsc --noEmit -p .   # both must be clean
git push origin tmp-deploy-mainN:main                              # triggers .github/workflows/deploy.yml
git checkout <working-branch>
git branch -D tmp-deploy-mainN
```

Pushing to `main` fires `deploy.yml` (GitHub Actions): `bun install` → `bun run deploy` (vite build + `wrangler deploy`) → pushes several secrets (`GOOGLE_SHEETS_CREDENTIALS`, Drive OAuth, Telegram media token, Resend, GH dispatch token). Poll via the Actions API/MCP tools to confirm it finished before treating a change as live.

**Admin/diagnostic endpoints in production**: the sandbox the AI runs in cannot reach the deployed Worker directly. The established pattern is `.github/workflows/admin-call.yml` (`workflow_dispatch`, input `path` = the request path + querystring) which does `curl` against `https://tanstack-start-app.empirerpg-forum.workers.dev<path>` and uploads the JSON response as a build artifact — read it back via the Actions job logs. Always hit a write-capable admin endpoint without `?confirmar=1` first (dry-run), inspect the output, then confirm.

## Architecture

**One Worker, two halves.** `src/server.ts` is the actual Cloudflare Worker entry (`wrangler.jsonc`: `main: "src/server.ts"`). Its `fetch` handler tries `handleEmpireApiRoutes()` (from `backend/src/index.ts` → `backend/src/routes/api.ts`) first; if that returns `null`, custom paths (`/api/catalogo`, `/api/flags`, `/api/log-error`, `/api/telegram-video/*`) are checked; everything else falls through to TanStack Start SSR (`@tanstack/react-start/server-entry`). The same file's `scheduled` export runs every 10 minutes (`wrangler.jsonc` → `triggers.crons`) for background jobs (TV participation processing, social-post cleanup, metacritic snapshot, pre-save album launches).

**Routing gotcha (hit repeatedly in this codebase's history): new exact-path API routes must be added to the `supportedPaths` Set in `backend/src/routes/api.ts`.** Routes under an already-covered prefix (`/api/empire-play/*`, `/api/editar*`, `/api/playlists*`, `/api/salvos*`, `/api/albuns-antigos*`, `/api/presave/*`) don't need this, but anything else that isn't in the Set or a recognized prefix silently falls through (`handleEmpireApiRoutes` returns `null`), and since most frontend fetches swallow errors with `.catch(() => [])`, a missing route manifests as a feature that "just doesn't do anything" with no visible error anywhere.

**`backend/src/controllers/`** has ~190 files. Most are real feature controllers (one file per domain: `gestaoController.ts`, `forumController.ts`, `preSaveController.ts`, `empirePlayController.ts`, etc.), but a large fraction are **one-off `adminDiag*`/`adminFix*` controllers** — disposable, narrowly-scoped diagnostic or data-repair endpoints written to investigate/fix one specific incident, wired into `api.ts` and never removed. This is the established pattern for any one-time data repair or live diagnosis: write a small dedicated controller (dry-run by default, `?confirmar=1` to write), wire it in, deploy, invoke via `admin-call.yml`, verify, and leave it in the tree (don't feel obligated to clean these up).

**Google Sheets is the source of truth**, accessed via `backend/src/services/googleSheetsService.ts`. Key points:
- `SPREADSHEETS` maps logical names (`principal`, `edicaoCharts`, `registrosCharts`, `chartsBase`, `usuarios`, `logsSistema`, etc.) to real spreadsheet IDs — there are ~13 separate spreadsheets, not one. `googleSheetsService.<key>.readValues(sheet, range)` / `.updateValues(...)` / `.appendRow(...)` / `.findRows(...)` are the entry points.
- A 15-second in-memory read cache + in-flight request coalescing exists per-isolate (added after a live-event traffic spike exhausted the Sheets API quota) — writes invalidate the relevant cache entry immediately.
- **Never use native `:append`** on a sheet with populated columns to the right of the data range — the Sheets API's "next free row" heuristic scans the *entire* row width, not just the requested range, and jumps far past the real data if far-right columns (formulas, calculated columns) are filled. Always find the real next-empty-row via a read, then `updateValues` on an explicit range instead.
- **Never write to a column driven by a spreadsheet formula** (e.g., `ARRAYFORMULA`-computed columns) — writing anything, including an empty string via `updateValues`, breaks the formula's spill for that row and every row below it. Only a genuine `values:clear` API call (not `updateValues([[""]])`) restores a cell to the truly-empty state a formula can spill back into.
- Prefer exact-match or exact-match-after-stripping-known-prefix comparisons over `.includes()`/substring matching when joining rows across sheets by title/name — this codebase has repeatedly hit false-positive cross-contamination bugs (one album's or artist's data bleeding into another's) from loose substring fallbacks.

**D1 (`CATALOGO_DB` binding, Cloudflare D1, `d1/schema.sql`)** is a partial, in-progress migration off Sheets for parts of the catalog (see `backend/src/services/musicasDbService.ts`, `catalogoDbService.ts`). Where it's used, Sheets generally remains the source of truth and D1 is a read-optimized mirror kept in sync by the write path — check whether a given read path actually queries D1 or still reads Sheets live before assuming freshness.

**Frontend structure**: `src/routes/` (TanStack Router file-based routes — dot-separated filenames encode nesting, e.g. `empire-play.gestao.album-antigo.tsx`), `src/components/EmpirePlay/` (the bulk of the game's feature UI), `src/lib/api.ts` (typed fetch wrappers for backend endpoints). `src/routeTree.gen.ts` is generated — never hand-edit it.

## Project-specific UI rule (buttons/pills/tabs with text)

Every button, pill, or tab that has text (label, name, title) needs:

1. **Never let the text escape the container.** In any flex container (a row of tabs, a horizontal selector, etc.), the item with long text needs `min-w-0` — without it, the text forces the item to grow past the available space even with `truncate` on the inner span (`truncate` alone isn't enough inside flex/grid without `min-w-0` on the direct ancestor).
2. **Safety margin**: real horizontal padding on the button (`px-1` minimum, never `px-0`/no padding), so text and icon never touch the edge.
3. Icon with `shrink-0` (keeps it from being squeezed when the text is long) and text with `truncate` (ellipsis instead of breaking layout).

This applies whenever a button/tab is added or a label is swapped for a longer one — no need to ask again each time.

### Tab bar with N fixed-width items (e.g. `grid-cols-N`)

**Explicit rule: text must never appear truncated with "..." in a tab bar.** An equal-width `grid-cols-N` breaks as soon as any label is longer than the others — on a narrow screen, `truncate`+`min-w-0` only stops the text from overflowing the card, but it still cuts off the word, which is also unacceptable.

In these cases, replace `grid-cols-N` with a horizontally **scrollable** row (the pattern already used across several app screens: `useDragScroll` + `StickyScrollArrowLeft`/`StickyScrollArrowRight`, see the example in `src/routes/social.tsx`, Empire Social's tab bar). Each tab gets `shrink-0` + real padding (sized to its own content, nothing truncated) and the row scrolls when everything doesn't fit. This guarantees text is always fully readable at any screen size — it's the "adjustable, responsive, and good-looking" shape that's already been requested and should be applied by default to any new tab bar, or when a new label is added to an existing one.
